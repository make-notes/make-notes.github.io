React优化​

减少渲染节点/降低渲染计算量​

  • 不要在渲染函数进行数组排序、数据转换、订阅事件、创建事件处理器等，渲染函数中不应该放置太多副作用。
  • 减少不必要的嵌套
  • 对于长列表，使用 react-window 或 react-virtualized 等库来虚拟化长列表，只渲染可见部分，提高渲染性能
  • 惰性渲染，比如tab选项卡，只需要渲染当前tab项，其他不用渲染。
  • 选择合适的样式方案，比如css > 大部分css-in-js > inline style

避免重复渲染​

  • 优化props 如果一个组件props过于复杂则意味着它违背了“单一职责”原理
  • 避免匿名函数和内联对象，因为它们会在每次渲染时创建新的引用，使用 useCallback 缓存函数，使用useMemo缓存计算结果，避免在每次渲染时重复计算
  • 使用不可变数据，比如immer、immutable等。
  • 使用shouldComponentUpdate、PureComponent 或 React.memo来减少重复渲染
  • 使用 recompose 精细化比对
  • 善用useReducer替换useState，可以合并多个状态更新，避免多次渲染

精细化渲染​

  • 代码分割和懒加载：例如使用 React.lazy 和 Suspense 实现代码分割和懒加载，减少初始加载时间。
  • 使用 Profiler来分析和识别性能瓶颈并做针对优化

Diff 算法​

React 的 Diff 算法用于高效地更新 DOM。它的主要目标是最小化 DOM 操作，从而提高性能。基本思想是：

  • 比较节点：React 会将新旧虚拟 DOM 树进行比较，找出差异。
  • 最小化更新：只更新实际发生变化的部分，而不是重新渲染整个树。
  • 优化策略：通过标记节点，优化节点的更新顺序和方式。

树的对比​

在 React 的虚拟 DOM 中，Diff 算法的主要任务是对比两个虚拟 DOM 树，找出它们之间的差异。

  1. 节点类型对比
    • 相同类型的节点： 如果新旧虚拟 DOM 节点的类型相同（例如，都是 div、span、组件等），则认为它们是同一个节点，需要进一步对比其子节点和属性。 对于同类型的节点，React 会尝试重用旧节点的 DOM 元素，并只更新其属性和子节点。
    • 不同类型的节点： 如果新旧虚拟 DOM 节点的类型不同，则 React 会卸载旧节点的 DOM 元素，并创建新的 DOM 元素。这意味着旧节点的整个子树将被替换。
  2. 元素属性对比
    • 简单属性： 对于简单属性（如 id、className、style 等），React 会直接比较属性值。如果属性值发生变化，React 会更新真实 DOM 中的对应属性。
    • 复杂属性： 对于复杂属性（如对象、数组），React 会递归比较这些属性的变化，确保更新正确。
  3. 子树对比
    • 同级比较： React 会对比虚拟 DOM 树中的子节点，找到它们的差异。React 会按照虚拟 DOM 树的顺序进行比较，并尝试最小化实现 DOM 的变更。
    • Key 属性： 在列表中，React 使用 key 属性来标识元素。key 是唯一的标识符，用于帮助 React 区分列表中的元素。使用 key 可以帮助 React 更准确地识别哪些元素发生了变化，从而更有效地更新 DOM。

实现细节​

React 的 Diff 算法实现细节包括：

  1. 深度优先遍历
    • React 使用深度优先遍历算法来比较两个虚拟 DOM 树。遍历过程中，React 会比较当前节点的类型、属性和子节点。
  2. 最小化 DOM 操作
    • React 的目标是最小化对真实 DOM 的操作，以提高性能。通过合并和优化差异更新，React 避免了频繁的 DOM 操作和重绘。
  3. Fiber 架构
    • React 16 引入了 Fiber 架构，以优化调和过程和支持更细粒度的控制。Fiber 架构通过增量渲染和优先级调度，进一步提升了 React 的性能和响应能力。

Fiber​

Fiber 是 React 16 引入的一种新的重渲染算法，用于改进和优化 Diff 算法。主要特点包括：

  • 增量渲染：允许中断和优先级调度，让长时间的渲染任务分解为小任务，提高用户交互的响应速度。
  • 任务优先级：支持不同优先级的任务，确保高优先级任务（如用户交互）能优先完成。
  • 错误处理：提供更好的错误边界，允许在渲染过程中捕获和处理错误。

介绍高阶组件（hoc函数）​

HOC 是一个函数，接收一个组件并返回一个新的组件。新的组件通常会增强或修改传入组件的行为或外观。HOC 最常用于跨多个组件复用逻辑。

HOC 的典型用法​

  • 逻辑复用：在多个组件中复用相同的逻辑。
  • 抽象状态：在多个组件中共享状态逻辑。
  • 修改 Props：在传递给组件的 props 上进行一些修改或增强。

react 有几种构建组件方式​

函数组件（Function Components）​

  • 函数组件是定义组件的简洁方式。它们通常是无状态的（即没有自己的状态），但自从 React 16.8 引入 Hooks 后，函数组件也可以拥有状态和其他功能。

类组件（Class Components）​

  • 类组件是基于 ES6 类的定义方式。它们可以拥有自己的状态和生命周期方法，在 Hooks 引入之前，类组件是处理有状态逻辑的主要方式。

对比​

  • 简洁性：函数组件通常比类组件更简洁，更易于编写和理解。
  • 性能：在某些情况下，函数组件可能会比类组件更高效，因为它们避免了一些类组件的开销。
  • 状态管理：在 Hooks 引入之前，类组件是唯一能够管理组件状态和生命周期的方法。现在，通过 Hooks，函数组件也能实现相同的功能。
  • 生命周期：类组件提供了一套完整的生命周期方法，而函数组件需要通过 Hooks（如 useEffect）来实现类似的功能。

其他构建方式​

除了上述两种主要的构建组件方式外，还有一些其他的技术和模式可以用于构建和组合组件：

  • 高阶组件（HOC）：高阶组件是一种用于复用组件逻辑的技术，通过函数接收一个组件并返回一个增强后的组件。
  • Render Props：通过一个函数作为 prop 将渲染逻辑传递给组件，使得父组件能够控制子组件的渲染。
  • Portals：用于将子节点渲染到父组件 DOM 层次结构以外的 DOM 节点中。

如何做页面样式切换（主题）​

创建主题上下文：​

  • 我们首先创建一个 ThemeContext，利用 React 的 Context API 来管理应用的主题状态。ThemeContext 包含当前的主题（例如 "light" 或 "dark"）和一个切换主题的函数 toggleTheme。

定义 CSS 变量：​

  • 在全局 CSS 文件中，我们使用 CSS 变量来定义不同主题的样式。例如，定义 --background-color 和 --text-color 变量，并根据主题的不同值设置这些变量。

使用 Context 提供主题：​

  • 在根组件中使用 ThemeProvider 包裹整个应用，使得应用中的任何组件都可以访问到主题上下文。

实现主题切换按钮：​

  • 创建一个按钮组件，通过 useContext 钩子获取当前的主题和切换主题的函数。当用户点击按钮时，调用 toggleTheme 函数来切换主题。

应用主题：​

  • 使用 useEffect 钩子在主题变化时更新 data-theme 属性，从而改变 CSS 变量的值，使得页面样式根据主题变化自动更新。

context优略势​

优势​

简化数据传递：​
  • 省去繁琐的 props 传递：通过 Context，可以避免一层一层地将数据作为 props 传递，特别是在组件树较深时。
全局状态管理：​
  • 方便全局状态管理：适用于管理全局状态，例如主题、用户认证信息等，可以在整个应用中共享状态而不必手动传递。
增强组件解耦：​
  • 减少组件间的耦合：使得组件可以直接访问共享状态或功能，减少了组件之间的直接依赖。

劣势​

性能开销：​
  • 重新渲染问题：每当 Context 的值发生变化时，所有订阅了该 Context 的组件都会重新渲染，可能导致性能问题。
复杂性增加：​
  • 组件树复杂：在大型应用中，多个嵌套的 Context 提供者可能会增加组件树的复杂性。
调试困难：​
  • 上下文追踪：调试 Context 相关问题可能比简单的 props 传递更复杂，特别是在多个 Context 嵌套的情况下。
滥用风险：​
  • 不必要的上下文：有时可能会过度使用 Context，将所有状态放入 Context 中，而实际上只需使用普通的 props 传递。

setState，是同步还是异步，调用后发生了什么​

  • setState 是异步的。当调用它时，React 不会立即更新状态和重新渲染组件，而是将更新排队处理。实际的状态更新和组件重新渲染会在稍后的时间发生。这种异步行为帮助优化性能，因为 React 可以批量处理多个状态更新。如果需要在状态更新后执行操作，可以使用 setState 的回调函数。

React Router​

React Router介绍​

路由声明和配置​

  • React Router 是一个用于在 React 应用中实现路由功能的库。它允许你根据 URL 渲染不同的组件，实现单页应用（SPA）的导航。

路由匹配​

  • 当 URL 变化时，React Router 会遍历定义的路由配置，尝试找到与当前 URL 匹配的路径。匹配机制包括以下几点：

    • 完全匹配：路径完全匹配时，Route 组件会渲染对应的组件。
    • 部分匹配：通过设置 exact 属性，控制是否需要完全匹配。
    • 动态参数：使用 :paramName 形式定义动态参数

路由组件​

  • Router
    • BrowserRouter：使用 HTML5 History API 实现 URL 导航。
    • HashRouter：使用 URL 哈希部分实现 URL 导航。
    • MemoryRouter：在内存中管理路由，适用于非浏览器环境。
  • Route
    • 定义路径和对应的组件。
    • 可以通过 component, render, children 三种方式渲染组件。
  • Switch
    • 渲染第一个匹配的路由，确保只有一个路由组件被渲染。

路由状态管理​

  • React Router 通过 history 对象管理路由状态，包括当前路径、导航历史等。history 对象提供了以下方法： 
    push：导航到新路径。
    replace：替换当前路径。
    go：导航到历史记录中的某个位置。
    goBack：导航到上一页。
    goForward：导航到下一页。

URL 变化监听​

  • React Router 使用 history 对象监听 URL 变化，并在 URL 变化时更新视图。具体步骤如下：
    • 监听 URL 变化：使用 history.listen 方法监听 URL 变化。
    • 匹配路由：URL 变化时，React Router 重新匹配路由。
    • 更新视图：匹配成功后，React 重新渲染对应的组件。

动态路由和嵌套路由​

  • React Router 支持动态路由和嵌套路由，通过这种方式，可以实现复杂的页面结构。

  • 动态路由

    • 动态路由通过在路径中使用参数实现。 
      <Route path="/user/:userId" component={UserProfile} />
    • 在 UserProfile 组件中，可以通过 match.params.userId 获取动态参数。

  • 嵌套路由

    • 嵌套路由允许在一个组件中定义子路由，实现多层级页面结构。 
      const App = () => (
        <Router>
          <Route path="/dashboard" component={Dashboard}>
            <Route path="/dashboard/profile" component={Profile} />
            <Route path="/dashboard/settings" component={Settings} />
          </Route>
        </Router>
      );

路由守卫​

  • React Router 支持在路由进入之前进行权限检查或其他操作，通过自定义组件实现路由守卫。 
    const PrivateRoute = ({ component: Component, ...rest }) => (
      <Route
        {...rest}
        render={props =>
          isAuthenticated() ? (
            <Component {...props} />
          ) : (
            <Redirect to="/login" />
          )
        }
      />
    );

    const App = () => (
      <Router>
        <Switch>
          <PrivateRoute path="/dashboard" component={Dashboard} />
          <Route path="/login" component={Login} />
        </Switch>
      </Router>
    );

URL 参数和查询字符串​

  • React Router 支持在组件中访问 URL 参数和查询字符串。
  • URL 参数
    • 通过 match.params 访问 URL 参数。
  • 查询字符串
    • 通过 location.search 访问查询字符串，使用 URLSearchParams 解析。

    • 渲染匹配的路由：如果找到匹配的 Route，则渲染其对应的组件。

react router 如何做到单页面刷新（实现），例如你修改路由路径，并不会造成页面重新刷新是如何做到​

1. 使用 HTML5 History API​

React Router 利用 HTML5 的 History API 进行客户端路由管理。这个 API 允许你在不重新加载页面的情况下修改浏览器的 URL 和管理历史记录。主要使用以下两个方法：

history.pushState()：用于添加新的历史记录条目并更新 URL。
history.replaceState()：用于替换当前的历史记录条目并更新 URL。

2. 捕获并处理 URL 更改​

Redux​

Redux 的数据流遵循以下顺序：​

  1. 用户触发事件：用户在应用中执行操作，如点击按钮。
  2. Dispatch Action：触发一个 action，描述用户的操作。
  3. Middleware（可选）：处理异步操作和其他副作用。
  4. Reducer：接收 action 和当前状态，计算并返回新的状态。
  5. Store 更新：更新 store 的状态。
  6. 视图更新：React 组件通过 connect 订阅 store 的变化，自动重新渲染。

实现原理​

  1. 创建 Store

    • 功能：Store 负责保存应用的状态，并提供获取状态、派发动作和订阅状态变化的功能。
    • 实现：定义一个 Store 类，包含以下方法：
      • getState()：返回当前的状态。
      • dispatch(action)：接收一个动作（action），通过 reducer 计算新的状态，并更新状态。
      • subscribe(listener)：允许订阅状态变化，当状态发生变化时调用传入的监听函数。

  2. 定义 Reducer

    1. 功能：Reducer 是一个纯函数，接收当前的状态和一个动作，根据动作返回新的状态。
    2. 实现：创建一个 reducer 函数，函数接受两个参数：
      • 当前状态
      • 动作对象
    3. 根据动作的类型（如 INCREMENT 或 DECREMENT），更新状态并返回新的状态。如果动作类型不匹配，则返回当前状态。

  3. 创建 Action

    1. 功能：动作是描述状态变化的普通 JavaScript 对象。每个动作至少包含一个 type 属性，表示动作的类型。可以包含其他属性（payload）来传递数据。
    2. 实现：定义几个函数，用于创建不同类型的动作，例如 increment() 和 decrement() 函数，分别返回对应的动作对象。

  4. 使用 Store 和 Reducer

    • 创建 Store 实例：使用 createStore 函数创建一个 Store 实例，并传入 reducer 函数来管理状态。
    • 订阅状态变化：使用 Store 的 subscribe 方法注册一个监听函数，这样每当状态发生变化时，监听函数会被调用。
    • 派发动作：使用 Store 的 dispatch 方法发送动作，触发状态更新。

  5. （可选）添加 Middleware

    • 功能：中间件用于扩展 Redux 的功能，例如处理异步操作或日志记录。
    • 实现：定义中间件的处理函数，在中间件中可以访问 dispatch 和 getState，并在动作派发之前或之后执行自定义逻辑。使用 applyMiddleware 函数将中间件应用到 Store。

redux-saga 应用​

redux-saga 是一个中间件，用于处理 Redux 应用中的副作用（例如数据获取、延迟操作等）。它的工作原理主要包括以下几个方面：

副作用管理：​

  • 在 Redux 应用中，副作用是指那些不直接影响应用状态的操作，比如发起网络请求。redux-saga 通过生成器函数来处理这些副作用。

生成器函数：​

  • redux-saga 使用生成器函数（function*）来处理异步操作。生成器函数可以暂停执行（使用 yield），并在需要的时候继续执行，这使得异步操作的逻辑更加清晰。

Saga 监听：​

  • 定义一个或多个 Saga 函数，这些函数监听 Redux 的 action。当这些 actions 被触发时，Saga 函数会执行对应的副作用操作，例如发起网络请求或者处理延迟操作。

Effects：​

  • redux-saga 提供了一些内置的 effects（例如 call、put、take），这些 effects 用于执行副作用：
call：用于调用异步函数并等待结果。
put：用于发出 action。
take：用于等待特定的 action。
Error Handling：redux-saga 允许你在 Saga 函数中处理错误，确保副作用操作的稳定性。

重绘（Repaint）​

  • 定义：重绘是指元素的外观发生变化，但不会影响布局。例如，改变元素的颜色、背景、opacity、可见性（如 visibility）、边框样式、css动画transform等。
  • 触发条件：只需要改变元素的外观属性。
  • 影响：重绘比回流消耗的性能相对较少，因为它不需要重新计算布局，只需要重新绘制受影响的元素。

回流（Reflow）​

  • 定义：回流是指元素的尺寸、布局或整个页面布局发生变化，需要重新计算元素的位置和几何形状。回流是更复杂、更耗时的操作。
  • 触发条件：任何影响元素尺寸、位置、显示隐藏、增加或删除元素的操作都会触发回流。例如，改变元素的宽度、高度、边距、填充、边框大小，或者插入、删除 DOM 元素等。
  • 影响：回流不仅会导致受影响的元素重新计算布局，还可能导致它的子元素、父元素甚至整个文档的重新布局，因此消耗性能较大。

如何优化重绘和回流​

  1. 批量操作 DOM：
    • 避免频繁的 DOM 操作，将多次 DOM 操作合并成一次。
    • 使用文档片段（DocumentFragment）批量插入多个元素。
  2. 使用 CSS3 动画和变换：
    • 使用 transform 和 opacity 进行动画，因为它们通常只会触发重绘，而不会触发回流。
    • 避免使用会触发回流的属性（如 width, height, margin, padding 等）进行动画。
  3. 减少布局计算：
    • 避免频繁访问会触发布局计算的属性和方法，如 offsetWidth, offsetHeight, clientWidth, clientHeight, getComputedStyle() 等。
    • 如果需要多次访问这些属性，可以将结果缓存起来，而不是每次都重新计算。
  4. 避免触发同步布局：
    • 在一个操作中读取和写入 DOM，会导致强制同步布局，应该先读取所有需要的值，然后再写入。
  5. 最小化 CSS 选择器的复杂性：
    • 使用高效的 CSS 选择器，避免使用过于复杂的选择器。
    • 使用类选择器和 ID 选择器，而不是后代选择器或通配符选择器。

内存回收​

内存回收的基本原理​

JavaScript 中，内存分为两种类型：栈内存和堆内存。

  • 栈内存（Stack Memory）：用于存储基本类型的变量和函数调用。在函数调用时，栈内存会自动管理这些数据，当函数返回时，栈内存会自动释放这些数据。
  • 堆内存（Heap Memory）：用于存储对象和引用类型。堆内存由垃圾回收器自动管理，当对象不再被引用时，垃圾回收器会自动释放这些对象占用的内存。

垃圾回收的主要算法​

这是最常用的垃圾回收算法，能够有效处理循环引用的问题。

  • 标记-清除（Mark-and-Sweep）：

    • 标记阶段：垃圾回收器从根对象（如全局对象和当前执行上下文中的局部变量）开始遍历，并标记所有可以从根对象直接或间接引用的对象。
    • 清除阶段：垃圾回收器遍历堆中的所有对象，释放那些没有被标记的对象占用的内存。

  • 引用计数（Reference Counting）：

    • 每个对象都有一个引用计数器，记录有多少个引用指向该对象。
    • 当一个新的引用指向该对象时，计数器加一；当一个引用不再指向该对象时，计数器减一。
    • 当计数器变为零时，该对象占用的内存可以被回收。
    • 引用计数的主要缺点是无法处理循环引用的问题。

垃圾回收的优化策略​

现代 JavaScript 引擎采用了多种优化策略来提高垃圾回收的效率和减少对程序运行的影响：

  • 分代垃圾回收（Generational Garbage Collection）：
    • 将内存划分为几代（通常为新生代和老年代）。
    • 新生代存储新创建的对象，这些对象往往生命周期较短，垃圾回收器会频繁回收新生代内存。
    • 老年代存储生命周期较长的对象，垃圾回收器会较少回收老年代内存。
  • 增量垃圾回收（Incremental Garbage Collection）：
    • 将垃圾回收过程分解为多个小步骤，穿插在程序的执行过程中，以减少一次性回收大量内存时的暂停时间。
  • 并发垃圾回收（Concurrent Garbage Collection）：
    • 垃圾回收器与应用程序同时运行，进一步减少因垃圾回收造成的暂停时间。
  • 紧凑化（Compaction）：
    • 回收未使用的内存后，重新整理内存布局，以减少内存碎片，提高内存分配效率。

手动回收​

  1. 解除对象引用
    • 当一个对象不再需要时，可以通过将对该对象的引用设置为 null 或 undefined 来解除引用。
  2. 清空数组和对象
    • 对于数组和对象，可以通过设置其长度为 0 或清空其属性来释放内存
  3. 移除 DOM 元素
    • 在浏览器环境中，移除不再需要的 DOM 元素可以显著减少内存使用。可以使用 removeChild 或 remove 方法来移除元素
  4. 取消事件监听器
    • 事件监听器会引用其绑定的元素，可能导致内存泄漏。确保在不再需要时移除事件监听器
  5. 处理定时器
    • 未清除的定时器也会导致内存泄漏。确保在不再需要时清除定时器
  6. 解除闭包中的引用
    • 闭包会保持对其上下文中的变量的引用，可能导致内存泄漏。确保在不再需要时解除闭包中的引用
  7. 使用 WeakMap 和 WeakSet
    • 对于某些情况，可以使用 WeakMap 和 WeakSet 来存储对象引用，这些引用不会阻止垃圾回收

JavaScript 使用单线程，通过执行栈、任务队列和事件循环处理同步和异步任务。微任务优先于宏任务执行，确保高效处理异步操作。

  • 单线程：JavaScript 一次只能执行一个任务。
  • 执行栈：用于处理同步任务，函数调用时压入栈顶，执行完毕后弹出。
  • 任务队列：存放异步任务的回调函数，如事件处理、定时器和网络请求。
  • 事件循环：不断检查执行栈是否为空，空时从任务队列中取出任务执行，保证异步任务的回调函数在同步任务完成后执行。
  • 宏任务和微任务：
    • 宏任务：如 setTimeout、I/O 操作。
    • 微任务：如 Promise 回调。每个宏任务执行完后，立即执行微任务队列。

  • 变量在块内部（如 中）声明后，只能在该块内部访问。
  • 使用 let 和 const 声明的变量具有块级作用域。

更改定位left之后发生了什么​

更改 left 定位会触发浏览器的重绘和可能的回流，以确保元素在新的位置正确显示

  • 样式更新：元素的 CSS left 属性会被更新，导致元素在水平位置上的改变。
  • 重绘：浏览器会重新计算元素的位置，并将其绘制到新的位置上，这个过程称为重绘（repaint）。
  • 回流：如果更改 left 属性导致了页面布局的改变（例如其他元素的位置也发生变化），浏览器还需要进行回流（reflow），这是一种更昂贵的操作，因为浏览器需要重新计算整个页面的布局。
